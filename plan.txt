## Phase 1 — Small live-utility features

[x] 1. Wait-time movement
Compare the latest valid wait with the previous snapshot and an approximately
30-minute-old snapshot. Return direction/delta from the attractions API and show
compact, accessible trend badges. Suppress misleading comparisons for stale,
closed, missing, or invalid observations.

[x] 2. Favorite ride alerts
Allow checked-in push subscribers to opt into favorite reopening alerts and
wait-below thresholds of 5, 10, 15, 20, or 30 minutes. Store preferences per
push endpoint, dispatch from fresh ride data, deduplicate for 30 minutes, and
remove expired push endpoints.

[x] 3. Show reminders
Allow reminders for individual future show occurrences, delivered 15 minutes
before start only while checked in. Persist per push endpoint and deduplicate by
date/show/time.

[x] 4. Quick service finder
Add a searchable /services page for first aid, toilets, accessible toilets,
guest service, ATMs, lockers, restaurants, Baby Switch, and the main entrance.
Store reviewed local data with source/update metadata and map-ready coordinates.

[!] 5. Ride suitability filters
Add minimum height/age, family/thrill, indoor/outdoor, water, accessibility,
weather sensitivity, and Baby Switch metadata. Add filters and a non-persistent
child-height input, with an official-information disclaimer.

[x] 6. Weather-aware suggestions
Recommend fresh, open indoor/show options in rain; water/shade/hydration options
in heat; less weather-sensitive options in wind; and low-wait favorites during
normal conditions. Label all suggestions as unofficial.

[x] 7. Completed-today tracking
Allow rides to be marked completed, stored locally by Europe/Berlin operating
date, automatically reset next day, independently of favorites and sync.

[x] 8. Offline last-known overview
Cache successful attraction, weather, show, and service data. Clearly label
offline/stale content and disable live-only actions. Version the service-worker
cache safely so installed iOS apps receive new code.

## Phase 2 — Ride history and predictions

[x] Add ride details with current status, today’s observed curve, predictions
for the rest of today and tomorrow, uncertainty bounds, best upcoming time,
support counts, and an experimental warning. Add an insights API and retain
closures/invalid data as gaps. Evaluate a stronger model after 14 complete days.
